# Portfolio Demo Sites

## When to Use

Use when designing, building, revising, or quality-checking standalone demonstration websites for a portfolio. Apply the rules across sibling concepts so each piece looks intentionally distinct.

## Visual differentiation

- Give every standalone concept its own image set; never reuse the same hero or key photograph across variants presented as different sites. Repeated imagery makes the portfolio look templated.
- Use one dominant neutral or base palette plus one intentional accent color. Add another strong color only when it has a clear semantic purpose and survives a visual review.
- Differentiate concepts through composition, typography, photography, interaction, and content structure—not by recoloring the same layout.
- When building several portfolio pieces, prefer different commercial verticals unless the user explicitly requests multiple directions for one client.

## Content integrity

- Mark invented businesses, products, prices, properties, doctors, testimonials, and performance claims as fictional demo content.
- Use licensed or clearly permitted images and preserve attribution requirements where applicable.

## Delivery quality gate

- Render and inspect desktop and mobile views before presenting a concept.
- Check image uniqueness across all sibling concepts, palette coherence, text readability, horizontal overflow, broken media, and interactive controls.
- Optimize local images to WebP or AVIF at their actual display dimensions; lazy-load content images below the fold while keeping the hero asset prioritized.
- State clearly when a preview image is stale and direct the user to the current HTML source of truth.
