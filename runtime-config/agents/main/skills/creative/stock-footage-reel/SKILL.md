# Ролик из стоков: от источников до готового MP4

## When to Use

Просьбы «сделай ролик или рилс из стоков», «нужны бесплатные кадры для монтажа»,
«проверь, можно ли брать видео отсюда», «вырежи кусок из этого Drive», подкаст или
аниме-материал для монтажа — либо любой другой случай, когда нужен готовый
вертикальный или горизонтальный ролик из чужого или бесплатного материала.

Проверенный на живых прогонах маршрут. Порядок важен: лицензия → материал →
ритм → титры → рендер → просмотр кадров глазами.

## 1. Сначала лицензия, потом кадры

| Источник | Публиковать? | Условия |
|---|---|---|
| coverr.co | да, коммерчески | без указания авторства; запрещено обучение ИИ и сервис-конкурент; бренды в кадре лицензией не покрыты |
| mixkit.co | да, коммерчески | соцсети/YouTube/реклама; нельзя CD/DVD, игры, ТВ и радио, регистрация трека в копирайт-сервисах |
| pexels.com | да, коммерчески | без указания авторства; нельзя продавать неизменённые копии, выдавать за свои на стоках, использовать людей в оскорбительном контексте |
| cinestudy.org | да, но с титрами | обязательны полные титры и хештеги проекта (#CINESTUDY #SONNYBOO и хештег проекта); © Sonnyboo |
| editstock.com | только демо-рил | платно (~$99 за 2 проекта); демо-рил и личный сайт можно, «Edited by» можно; нельзя IMDb, фестивали, коммерческое распространение; для туториалов отдельное условие со ссылкой на EditStock в описании |
| rawfootagelab.com | **нет** | каталог ссылок на YouTube, лицензий не выдаёт («we grant no licenses or rights to the third-party video content»); в каталоге есть пиратские аниме-эпизоды |

Аниме-нарезки (Demon Slayer и прочие тайтлы) не публиковать — страйк, снятие видео,
блокировка, а для портфолио ещё и репутационный минус. Аниме-стилистику делать
генерацией или кодом (HyperFrames), либо брать паблик-домен. Материал из ссылочных
каталогов — только для практики в стол.

## 2. Где брать файлы

Coverr — лучший автоматический путь, прямые mp4 на CDN:

    curl -sL -A "Mozilla/5.0" https://coverr.co/stock-video-footage/vertical > cv.html
    # в HTML лежит JSON-LD VideoGallery: name, description, duration, contentUrl
    # прямые файлы: https://cdn.coverr.co/videos/coverr-<slug>-<id>/1080p.mp4
    ffmpeg -ss 6 -t 2.5 -i in.mp4 -an -vf "scale=1080:-2,crop=1080:1920,fps=30" \
      -c:v libx264 -preset veryfast -crf 18 -pix_fmt yuv420p out.mp4

Музыка Mixkit (прямые mp3 находятся на страницах жанров):

    curl -sL -A "Mozilla/5.0" https://mixkit.co/free-stock-music/breakbeat/ > g.html
    # ссылки вида https://assets.mixkit.co/music/<id>/<id>.mp3

Проверять каждый клип до монтажа: ffprobe плюс вытащить кадр и **посмотреть глазами**.
Признаки плохого выбора: светлый яркий фон под текстом, чужие логотипы и торговые марки,
чужой интеллектуальный контент (NFT-картинки, интерфейсы, бренды).

## 3. Большие файлы на Google Drive (до десятков ГБ)

Прямая ссылка не открывается — Drive отдаёт HTML-заглушку «Quota exceeded» или
confirm-форму, а монтажные программы этот диалог пройти не умеют. Файл при этом
отдаётся по байтовым диапазонам, этим и пользуемся.

Инструмент — `/home/vottak/Проекты/tools/gdrive-proxy.py`, локальный range-прокси.
Он проходит подтверждение, держит cookie и превращает любой запрос в закрытое окно 8 МБ.

    python3 /home/vottak/Проекты/tools/gdrive-proxy.py 8787 &
    ffprobe "http://127.0.0.1:8787/<FILE_ID>/take.mp4"
    ffmpeg -ss 90 -t 6 -i "http://127.0.0.1:8787/<FILE_ID>/take.mp4" -c copy out.mp4

Грабли, проверенные на практике:

- незакрытый диапазон (`bytes=0-`) и запрос всего файла возвращают HTML-страницу квоты,
  закрытое окно отдаёт видео — 206 с честным `Content-Range`;
- размеры файлов папки Cinestudy-подкаста: 26 МБ, 6.7 ГБ, 13.4 ГБ, 14.7 ГБ, 36 ГБ
  (4K UHD, 23.976 fps, звук 48 кГц), так что качать целиком не нужно — режем нужные секунды;
- вырезание 6 секунд 4K через прокси — около минуты и ~47 МБ, поэтому сначала
  выбирать таймкоды, потом резать;
- если и диапазоны упираются в квоту — брать версии проекта, выложенные владельцем
  на YouTube (ссылки есть на странице проекта Cinestudy).

## 4. Ритм: резы на битовую сетку

Инструменты из HyperFrames Student Kit (`~/Проекты/hyperframes-student-kit`):

    node .claude/skills/motion-showreel/scripts/music-grid.mjs <track.mp3> --bpm 128
    node .claude/skills/motion-showreel/scripts/beatgrid.mjs --period 0.4644 --length 15 \
      --chapters "01:4, 02:8, 03:4, Flurry:4, End:rest"

Проверка готового рендера тем же набором:

    node .claude/skills/motion-showreel/scripts/analyze-reference.mjs renders/x.mp4 qa \
      --fps 6 --bpm 120 --phase 0.018

Он печатает резы, яркость по полусекундам, RMS и отклонение резов от сетки в мс.
Отклонение меньше половины кадра (16 мс при 30 fps) — норма. Замер из рабочего ролика:
120.01 BPM, фаза 0.018 с, сетка 0.5 с, резы 2.500 / 5.000 / 7.500 / 10.000, отклонение −18 мс.

Звук: нормализовать и приглушить конец.

    ffmpeg -t 12 -i track.mp3 -af "loudnorm=I=-14:TP=-1.5:LRA=11,afade=t=out:st=11.5:d=0.5" \
      -c:a aac -b:a 192k <project>/assets/bed.m4a

## 5. Титры в HyperFrames

Готовая модель — `~/Проекты/hyperframes-student-kit/video-projects/reel-stock` (стоки)
и `reel-overlay` (титры на пустом фоне). Правила, добытые ошибками:

- видео кладётся в **необёрнутый** div, у самого `<video>` есть `data-start`,
  `data-duration`, `data-track-index`; анимировать `<video>` нельзя — зависает;
- несколько планов надёжнее сначала склеить в один файл через concat demuxer —
  секвенция из нескольких `<video>` в композиции не гарантирована;
- каждое появление титров — отдельный `.clip` со своими `data-start`/`data-duration`;
  окно клипа и есть момент склейки, отдельные твины прозрачности не нужны;
- **одно свойство — один твин на элемент**: кадры снимаются не по порядку, и свойство,
  анимированное дважды (вошло, потом вышло), может залипнуть на перемотке;
- затемнение под текстом (радиальный скрим в зоне заголовка) обязательно, иначе белый
  текст теряется на светлых кадрах; тени вида `0 10px 36px rgba(0,0,0,.8)`;
- шрифт с кириллицей и весом 900 — `'Noto Sans','DejaVu Sans'`;
- длинная строка ломается на две и ломает вёрстку, поэтому для неё отдельный класс
  с меньшим кеглем;
- линт `npx hyperframes lint`; предупреждение `timeline_track_too_dense` лечится выносом
  сцен в `compositions/*.html` и монтированием через `data-composition-src`.

## 6. Тексты в кадре

- Никакого монтажного жаргона — «рез по биту», «таймлайн», «кейфрейм» зритель
  не понимает. Приём оставляем внутри, в кадре показываем результат.
- Строка короткая, 2-4 слова; ключевое слово жёлтым, остальное белым.
- Хук на каждый план — 3 строки на первом, 2 на следующих, финал — призыв.
- Проверка подлинности: если автор ролика сам не понял надпись, зритель тем более.
- Сноска об источниках (`footage — coverr.co · music — mixkit.co`) по лицензии
  не обязательна, но честна; для Cinestudy вместо сноски — полные титры по их списку.

## 7. Финальная проверка (не пропускать)

    ffprobe -v error -show_entries format=duration,size \
      -show_entries stream=codec_type,codec_name,width,height,nb_frames,r_frame_rate \
      -of default=noprint_wrappers=1 renders/x.mp4
    ffmpeg -hide_banner -i renders/x.mp4 -af volumedetect -f null -   # mean/max dB

Обязательно вытащить кадры из каждого плана и **посмотреть их** — рендер бывает чёрным,
пустым или с налезающим стикером, а по логам при этом «успешный». Черновик —
`--quality draft` (12 секунд рендерятся 40-90 с), для публикации — `--quality high`.
