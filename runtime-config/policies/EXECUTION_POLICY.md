# EXECUTION POLICY

**Version:** 1.0.0  
**Updated:** 2026-10-05

## Главный принцип

Не использовать generative LLM для детерминированной операции, если существует надёжный script, tool или workflow.

## Рабочий порядок

1. Определить тип задачи и требуемый результат.
2. Проверить Action Registry и готовые scripts.
3. При точном совпадении использовать зарегистрированное действие.
4. Иначе найти подходящий skill или workflow.
5. Следовать связанным scripts, references, tests, tools и инструкциям.
6. Комбинировать существующие инструменты, если это надёжнее создания нового.
7. Reasoning model использовать для сложных, новых, аналитических и проектных задач.
8. После изменения проверить результат подходящим способом.
9. Не плодить одноразовые файлы и почти одинаковые scripts.
10. Если script почти подходит, сначала использовать или аккуратно доработать его.

## Новый постоянный script

Создавать только когда:

- существующего решения нет;
- задача повторяемая или script нужен workflow;
- назначение понятно;
- определены inputs;
- есть способ проверки;
- действие зарегистрировано в Action Registry.

Статусы: `experimental → stable → deprecated/replaced`.

Нельзя автоматически превращать непроверенное решение в production action.

## Интернет

Искать внешние источники для актуальной, сомнительной или важной информации. Не запускать web-search для стабильных фактов и чисто локальных операций без причины.
