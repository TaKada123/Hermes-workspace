# MEMORY POLICY

**Version:** 1.0.0  
**Updated:** 2026-10-05  
**Mode:** B — сохранять очевидно долгосрочные полезные сведения самостоятельно.

## Уровни памяти

### CORE

Очень маленькое постоянно доступное ядро: форма обращения, язык, устойчивый стиль общения, ключевые предпочтения и долгосрочное направление.

### DOMAIN MEMORY

Домены: `coding`, `engineering`, `AI`, `visual`, `documents`, `home`, `finance`. Profile получает только явно разрешённые разделы. Пересечение памяти разрешается точечно, например read-доступ `coding` к конкретному разделу `engineering`, но не ко всему домену.

### EPISODIC / ARCHIVE

История задач, проектов и решений. Не загружать постоянно. Использовать retrieval только когда current request + CORE + разрешённой DOMAIN MEMORY недостаточно.

### ACTIVE TASKS

Временные планы и состояния хранятся отдельно по `ACTIVE_TASKS_POLICY.md`; они не являются постоянной памятью.

## Типы записей

`fact | preference | rule | goal | state`

Временный `state` не превращать автоматически в постоянный `fact`.

Для изменяемой записи по возможности хранить:

```yaml
type: fact|preference|rule|goal|state
value: ...
updated_at: ISO-8601
source: user|file|project|verified_external
provenance: ссылка или идентификатор источника
confidence: 0.0-1.0
status: active|archived|superseded
```

## Запись и обновление

- Перед сохранением определить: новый факт, уточнение или замена старого.
- Не дублировать существующую запись.
- Устаревшее обновлять, архивировать или помечать `superseded`.
- Предположения агента не сохранять как факты.
- Для важных фактов по возможности сохранять provenance.
- Актуальный исходный файл, БД или проектный источник важнее старой памяти и session history.

## Не сохранять автоматически

- разовые разговоры и эмоции;
- временные планы и случайные покупки;
- медицинские сведения;
- пароли, API keys, tokens и другие секреты;
- лишние сведения о третьих лицах.

Медицинскую информацию сохранять только по прямой просьбе. Контакты хранить отдельно и передавать агентам только по необходимости.

## Секреты

Никогда не хранить секреты открытым текстом в памяти, skill, логах или profile-файлах. Значение хранится в защищённом secret storage; память может знать только имя секрета и место хранения.

## Изоляция

Специализированный агент не видит автоматически память, файлы и инструменты других областей. Доступ выдаётся явно контрактом Profile и в минимальном объёме.
